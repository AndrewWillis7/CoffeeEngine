=======================================================================
 CoffeeEngine -- LegRig knob reference
 (scripts/objects/leg_rig.lua)
=======================================================================

Everything here is passed as the config table to LegRig.new(config), or
-- for the Player -- as the 5th argument to Player.new(x, y, w, h, cfg).
Anything omitted falls back to LegRig.Defaults. Pass `false` instead of
a table for a legless actor: every per-frame call becomes a no-op and
GetStandHeight() returns 0.

All distances are TEXELS (world units), not screen pixels.
+Y IS DOWN, matching Vector2.h.

-----------------------------------------------------------------------
 1. MODULES -- the four drawn pieces of a leg
-----------------------------------------------------------------------

Each is a table { width = N, height = N, color = {r, g, b, a} }.
height = 0 removes that module entirely.
Widths and heights are rounded to whole texels on the way in.

  legging   Upper leg (thigh). Drawn hip -> knee.
            default { width = 5, height = 9, color = {0.30, 0.33, 0.50} }

  knee      Joint cap. ALWAYS axis-aligned, never rotated. Drawn last of
            the two bones so it covers the seam where their staircases
            meet. Its HEIGHT also extends the upper IK bone (see L1
            below) -- that's the "leg format" knob: raising it pushes the
            bend point further down the leg.
            default { width = 5, height = 2, color = {0.20, 0.22, 0.34} }

  boot      Lower leg (shin). Drawn knee -> ankle.
            default { width = 6, height = 5, color = {0.14, 0.12, 0.16} }

  foot      Axis-aligned block hanging below the ankle. Never rotates.
            Colour defaults to the boot's if omitted, so a config written
            before feet existed still gets a matching one.
            default { width = 7, height = 2 }

DERIVED (read-only, computed in InitLegRig):
  L1     = legging.height + knee.height     -- upper IK bone
  L2     = boot.height                      -- lower IK bone
  chain  = L1 + L2                          -- hip -> ankle reach
  length = chain + foot.height              -- hip -> SOLE reach

*** THE SINGLE MOST IMPORTANT TUNING RULE ***
Keep L1 and L2 roughly EQUAL. The knee's sideways offset saturates once
one bone dominates, so a long thigh against a short shin bends correctly
and still looks like a straight stick. Measured on the stock player:

  legging 11 + knee 3 vs boot 5   ->  knee travels 4.2 -> 4.9 texels
                                      across the whole gait (0.6 total)
  legging  7 + knee 2 vs boot 8   ->  knee travels 2.9 -> 6.0 texels
                                      (3.1 total -- 5x the range)

A short shin also has too little length to visibly change ANGLE against
the thigh, which is the part the eye actually reads as "a knee".

-----------------------------------------------------------------------
 2. POSTURE
-----------------------------------------------------------------------

  stand         0.88    Fraction of `length` the hip rests at while
                        standing. 1.0 = dead straight: geometrically
                        right, visually stiff, and it parks the IK on its
                        singular pose so the knee has no consistent side
                        to pop toward. Stay below ~0.95.

                        *** COUPLED TO THE TORSO. *** standHeight is
                        round(length * stand), and Player.new forces the
                        torso to an EVEN number of texels (see section 8).
                        Change `stand` or any module height and re-check
                        that the torso still lands even, or the hip seam
                        starts crawling. Stock player: length 19,
                        stand 0.95 -> standHeight 18 -> torso 14. Good.

  bob           1       Peak rise of the hips at mid-stance, WHOLE texels
                        (it is rounded). Driven off the swinging foot's
                        own lift, so it needs no phase of its own. 0 off.
                        Fractional values are pointless -- they round.
                        The owner must apply GetBobOffset() to its torso
                        at draw time; see Player:Draw.

  footLean      1       How far forward of the ankle the foot block sits.
                        0 = a stump; 1-2 = a toe that reads as a facing
                        direction even while standing still.

-----------------------------------------------------------------------
 3. GAIT
-----------------------------------------------------------------------

  stride        20      World distance travelled per FULL cycle (both
                        legs step once). Phase advances with DISTANCE,
                        not time, so this automatically matches whatever
                        speed the actor happens to move at -- there is no
                        separate animation rate to keep in sync.

  stanceRatio   0.58    Fraction of the cycle each foot spends PLANTED.
                        0.5 is degenerate: one foot lifts the instant the
                        other lands, so the actor is never on two feet
                        and it reads as a rocking limp. Above 0.5 buys a
                        double-support window. Below 0.5 reads as a jog.

                        *** DO NOT set the sweep amplitude by hand. ***
                        It is derived as stride * stanceRatio * 0.5,
                        which is the exact value that makes a planted
                        foot hold still in WORLD space while the body
                        moves over it. Any other number and feet visibly
                        ice-skate.

  swingFrames   4       Discrete poses the AIRBORNE foot may occupy on
                        its way forward -- the "hand-animated" knob.
                        Continuous interpolation slides the foot through
                        every subpixel position, which on a chunky grid
                        reads as a foot melting forward; quantizing gives
                        the crisp pop of drawn sprite animation.
                        Lower = chunkier. 0 = fully continuous.
                        Only the swing is quantized; stance stays exactly
                        linear because that is what the no-slide math
                        depends on.

  stepHeight    3       Peak lift of a swinging foot. This is also your
                        main KNEE FLEX control -- lifting the foot
                        shortens hip-to-ankle, which is what bends the
                        knee. Raise it if the walk looks stiff.

  idleSpeed     4       |vx| below this counts as standing still.

  gaitBlend     8       How fast the walk fades in/out (exponential
                        rate, framerate independent). Higher = snappier.

-----------------------------------------------------------------------
 4. STANCES -- named idle poses
-----------------------------------------------------------------------

  stances               Table of name -> per-leg offset list, indexed
                        exactly like `legs` (entry 1 is leg 1).
                          x  moves the foot along the FACING direction
                             (+ = forward), so a symmetric +/- pair is a
                             legs-apart stance in side view.
                          y  LIFTS the foot when negative (foot up on a
                             rock). Positive y drives the foot into the
                             ground, where the ground clamp eats it.
                        default:
                          { default = {}, apart = { {x=3}, {x=-3} } }

  stance        "default"   Which pose is active at construction.

  stanceBlend   9       Rate the feet ease between stances. Toggling
                        looks like shifting weight rather than snapping.

Stances fade in by (1 - gait blend) -- they only show while the actor is
NOT walking, so a stance can never disturb the stride math. Offsets are
applied BEFORE the ground query, so a foot placed out to the side lands
on the terrain height over THERE, not the centre's -- it stands
correctly on a slope.

  rig:SetStance("apart")
  rig:GetStance()                 -> current name
  rig:ToggleStance("apart")       -> flips apart <-> default
  rig:ToggleStance("a", "b")      -> flips between two named poses

Unknown names are ignored rather than raising -- a stance is cosmetic
and a typo in a level script should not take the legs away.

-----------------------------------------------------------------------
 5. GROUND & RECOVERY
-----------------------------------------------------------------------

  snapDistance  6       How far BELOW full extension to keep searching
                        for ground. Lets a foot reach into a dip instead
                        of dangling over it; past this the leg hangs
                        straight (walking off a ledge).

  smoothing     24      Rate a foot eases across a DISCONTINUITY -- a
                        step up, a facing flip, landing after a jump.
                        NOT a lag filter on foot position: filtering the
                        position makes a planted foot chase the body and
                        re-introduces the ice-skating (~4 texels of slide
                        per stance, measured). Continuous motion is
                        tracked exactly; only the leftover offset decays.

  airTuck       0.68    Fraction of `length` the feet hang at while
  airReach      0.97    RISING vs FALLING. Tucked up, reaching down.

-----------------------------------------------------------------------
 6. PER-LEG -- the `legs` list
-----------------------------------------------------------------------

Each entry describes one leg. The list length is the leg count, so this
is also how you build a four-legged creature.

  hipX     0      Hip offset from the body centre, LOCAL texels,
                  mirrored by facing. The stock rig uses +1 / -1: with
                  both at 0 the sweep is the only thing separating the
                  legs, so the moment the actor stops walking the two
                  converge to an identical pose and the silhouette
                  collapses to a single leg.

  phase    auto   Position in the gait cycle, 0..1. 0.5 = perfectly
                  opposed. Defaults to evenly spaced ((i-1) / #legs).

  layer    "front"  Which canvas -- and therefore which side of the
                  torso -- this leg draws on. "front" or "back".

  shade    1.0    Flat multiplier BAKED INTO THE PIXELS (not a body
                  tint, which would hit a whole canvas at once). Fakes
                  depth on the far leg with no second set of art.
                  It multiplies toward BLACK, so how far it can be
                  pushed depends on how dark the modules already are --
                  0.62 over an already-dark boot took the far leg below
                  a night background and it stopped reading at all.
                  0.70 is about the floor for dark palettes.

  bend     1      +1 bends the knee toward facing (forward, human).
                  -1 bends it backward (bird / digitigrade ankle).

  legging / knee / boot / foot
                  Optional per-leg module overrides, same shape as
                  section 1. This is how you build a limping or
                  asymmetric creature without a second rig class.

-----------------------------------------------------------------------
 7. METHODS
-----------------------------------------------------------------------

Wiring:
  rig:SetOwner(body, hipLocalY)   Torso body + hip offset from its
                                  CENTRE. hipLocalY is rounded to a
                                  whole texel -- it anchors the leg
                                  canvas's pixel grid to the owner's.
  rig:SetSolids(solids)           Cache the ground set so UpdateLegs(dt)
                                  can be called with no second argument.

Per frame (call AFTER the owner's physics/collision has resolved):
  rig:UpdateLegs(dt, solids)
  rig:DrawLegs("back") / ("front") / (nil for both)
  rig:Draw()                      back then front

Queries:
  rig:GetStandHeight()            Texels of the actor's height that are
                                  leg. Subtract from total height to
                                  size the torso.
  rig:GetLegLength()              Shortest leg's hip -> sole reach.
  rig:GetBobOffset()              Whole-texel torso draw offset, this
                                  frame. Negative is up.
  rig:GetFootPosition(i)          World SOLE position (not the ankle) --
                                  the point footstep dust/sound wants.
  rig:GetFacing() / SetFacing(f)
  rig:HasLegs()

-----------------------------------------------------------------------
 8. CONSTRAINTS YOU CAN BREAK BY ACCIDENT
-----------------------------------------------------------------------

TORSO HEIGHT MUST BE EVEN.
  Player.new forces this. hipLocalY is torsoHeight / 2, and the leg
  canvas is anchored to the owner's centre by that offset -- an odd
  torso puts the canvas's pixel grid half a texel off the torso's, so
  the two round to different texels under quad.vert's u_PixelSnap and
  the hip seam crawls as the actor walks. Canvas dimensions are forced
  even for the same reason.

INTEGER-ONLY VALUES.
  bob, footLean, hipX and every module width/height are rounded. A
  fractional value there does not give you a fractional result, it
  gives you a rounded one plus the illusion that you tuned something.

DON'T HAND-TUNE THE SWEEP AMPLITUDE.
  See stanceRatio. It is derived for a reason.

REBUILDING.
  InitLegRig(config) can be called again to rebuild from a new config.
  The old canvases are dropped; ActorRegistry owns them and reclaims
  them on the next hot-reload.

-----------------------------------------------------------------------
 9. QUICK RECIPES
-----------------------------------------------------------------------

Walk looks stiff / no visible knee
  -> Balance L1 against L2 first (section 1). Then raise stepHeight.
     Lowering `stand` deepens the resting bend but also shortens the
     torso -- re-check the even rule.

Walk looks like it is melting / too smooth
  -> Lower swingFrames (3, or even 2).

Feet slide along the ground
  -> Something overrode the derived amplitude, or stanceRatio was
     changed without letting the amplitude re-derive. Both feet sliding
     equally is the signature.

Character looks tippy / never on two feet
  -> Raise stanceRatio above 0.5.

Far leg disappears into a dark background
  -> Raise its `shade`, and lighten the boot/foot rather than relying
     on shade to do the separating.

Legs merge into one shape while standing
  -> Give the legs non-zero, opposite hipX, or set a stance.

Digitigrade / bird creature
  -> bend = -1, and a short legging with a tall knee to push the bend
     point down the leg.

Four legs
  -> Four entries in `legs` with phases 0, 0.5, 0.25, 0.75 and hipX
     spread front/back. Front pair on "front", rear pair on "back".
